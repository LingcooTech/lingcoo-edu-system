## 0. 一句话定位

**卖给单个培训机构、装在自己服务器上自用的可自部署软件**(非 SaaS)。
**一套部署 = 一家机构 = 一个品牌**;机构内部有多校区 / 老师 / 课程,但这些是机构内部实体,不是"租户"。首个落地场景:美智优品成长教室(硬笔书法 / 创意美术 / 幼小衔接)。

## 1. 核心商业模型:我们卖什么

### 1.1 两类东西要先分清

- **教学资源(供给 / 成本,本身不卖)**:老师、课程(教什么)、校区 / 教室、班级、课次。这些是产能和库存。
- **售卖物(收入)**:**课时**。家长买的不是"老师"也不是"课程"本身,而是"孩子有权来上 N 节某门课"。

> 一句话:**课程是"教什么",课时是"卖什么"。**

### 1.2 商品分层(本期只做两层)

| 概念               | 在本业务里                        | 例子                          | 落地实体                        |
| ------------------ | --------------------------------- | ----------------------------- | ------------------------------- |
| **Product 产品**   | 课程(教学内容本身)                | 硬笔书法基础班                | `courses`                       |
| **可售卖 SKU**     | 课时包(多少课时 + 价格)           | 12 课时包 ¥1280               | `course_packages`               |
| _Offer 促销(后期)_ | 规格 + 折扣价 + 有效期 + 活动绑定 | 暑期特惠 12 课时 ¥980,限 8 月 | _暂作课时包可选字段,后期再独立_ |

### 1.3 售卖规则(已拍板)

- **课程只通过课时包售卖**。课程退化为"目录 / 教学内容",**不自带售价**(如需展示可用所挂课时包的"起价")。
- 想卖的课程**必须至少挂一个课时包**;没挂包的课程**只能看 / 只能约试听,不能买**。
- 价格、课时数只定义在**课时包**上,单一来源,不再课程、课时包两头定价。

## 2. 身份与账号模型

### 2.1 统一身份 + 角色

**一张账号表 + `role` 字段**,一个登录接口,令牌里带角色。角色三种:

| 角色             | 谁                                      | 怎么产生                                  | 入口                  |
| ---------------- | --------------------------------------- | ----------------------------------------- | --------------------- |
| **管理员 admin** | 老板 / 运营(本期不再细分顾问·教务·财务) | 预置 / 由管理员开通                       | Web 管理后台 `/admin` |
| **老师 teacher** | 授课老师                                | 由管理员开通,关联到老师档案               | 微信小程序老师工作台  |
| **家长 parent**  | 学员家长                                | **下单成交后按手机号自动创建** / 微信绑定 | 微信小程序家长中心    |

### 2.2 "档案记录" ≠ "登录账号"

- **只有档案、不登录的**:
  - **孩子(学员 `students`)**:永远不登录,一份档案 + 课时账户。
  - **老师(作为教学资源 `teachers`)**:排课 / 考勤用的资源记录(与"老师账号"是两回事,通过关联打通)。
  - **家长(作为联系人 / 监护人 `guardians`)**:CRM 要联系的人,哪怕从不登录也有记录。
- **需要登录账号的**:管理员、老师、家长(见上表)。

### 2.3 手机号是身份去重锚点

同一个手机号,贯穿 **线索 → 联系人 → 家长账号 → 某孩子的家长**,始终视为同一个人,**绝不重复建档**。

## 3. 访问与登录

### 3.1 终端职责

Web 只保留官网和管理后台;老师、家长业务只在微信小程序维护:

| 角色             | 登录后看到                                                                                                        |
| ---------------- | ----------------------------------------------------------------------------------------------------------------- |
| 公开访客(未登录) | 机构首页、课程、课时包、试听课;提交试听报名;**免登录下单买课时包**                                                |
| 家长             | 小程序**家长中心**:孩子课时余额、课表、订单、签到、作业、互动                                                     |
| 老师             | 小程序只显示“工作 / 我的”两个底部入口;工作页承载课表、班级、学员、排课、点名、点评与作业,我的页维护账号与个人介绍 |
| 管理员           | Web `/admin` 独立登录后进入管理后台                                                                               |

### 3.2 /admin 门禁

- 未登录访问 /admin → 跳转 `/admin/login`;
- 登录但非管理员(家长 / 老师)访问 /admin → 挡住(无权限);
- 仅 `role=管理员` 放行。
- 后台有独立登录页,登录时明确请求 `admin` 身份。

### 3.3 登录方式(本期)

- **邮箱 或 手机号 + 密码**(两种标识符都认)。
- **家长账号**:下单成交后自动创建;在微信小程序按手机号登录或绑定微信。
- **老师 / 管理员账号**:由管理员开通,给默认密码 + 强制首登改密。
- **忘记密码(短信接入前的妥协)**:有邮箱 → 邮箱找回;否则 → 管理员在后台手动重置为默认密码。
- **短信验证码:后期接入**(等买短信包),作为登录 / 找回的增强,不改现有结构。

## 4. 营销获客转化全链路

### 4.1 漏斗

```
线下触点(海报 / 传单 / 朋友圈 / 微信群,各带"渠道 + 活动"二维码)
  → 扫码进 H5 落地页(URL 自动带 source=渠道 & campaign=活动 & course=课程)
  → 看课程 / 试听课
  → 提交试听报名(手机号 + 孩子信息)        ← 生成线索,来源归因焊死在线索上
  → 顾问后台跟进(跟进记录 + 状态流转)
  → 约到店试听 → 签到
  → 试听后跟进 → 成交
  → 买课时包(在线支付 / 手动登记)          ← 线索转学员,建档 + 关联家长 + 自动建家长账号
  → 入班 → 上课签到 → 消课 → 余额预警 → 续费
```

### 4.2 "打通"的本质:三条贯穿线

1. **归因链**:二维码参数 → 线索 → 订单 / 学员,一路带着渠道 / 活动。让报表能算每个渠道 / 活动的 ROI(投入 → 线索 → 到店 → 成交 → 收入)。
2. **身份链**:手机号把 线索 / 联系人 / 家长账号 / 学员 串成一个人。
3. **状态链**:动作自动驱动状态,而不是靠人手动改(见 4.3)。

### 4.3 线索状态机

`new 待联系` → `contacted 已联系` → `trial_booked 已约试听` → `trial_attended 已试听` → `paid 已缴费` → (`follow_up 后续跟进` / `invalid 无效`)

- 提交试听报名 → 自动 `trial_booked`;
- 试听签到 → 自动 `trial_attended`;
- 成交下单 → 自动 `paid` 并触发"转正式学员"。

## 5. 免登录下单(核心流程)

**核心:用"手机号"当身份锚点,不是"账号"。买东西全程不需要登录。**

1. 扫码进 H5(带 `source / campaign / course` 归因参数);
2. 选课时包 → 点购买;
3. 填**最少信息**:家长手机号 + 孩子姓名(年级可选),**不设密码、不注册**;
4. 支付(微信 / 支付宝),或生成**待收款订单**由前台手动收。

**成交后(在线支付成功 / 管理员标记订单已收款),系统自动:**

- 按**手机号**找 / 建 **联系人(guardian)**——同号即同人;
- 建 / 找**孩子(学员)**档案,挂到该家长名下;
- 生成**订单**(关联 课时包 / 课程 / 学员 / 家长,带上来源归因);
- 给"学员 + 课程"的**课时账户充值**对应课时,记一条课时流水;
- CRM 里记为"已成交线索"(或匹配到同手机号旧线索并标记转化);
- **自动建家长账号**(默认密码 = 手机号后 6 位),成功页提示登录改密。

## 6. 教学与消课

### 6.1 主干

```
课程 → 课时包 → 订单(购买) → 课时账户(充值) → 入班 → 排课次 → 签到 → 消课 → 余额预警 → 续费
```

### 6.2 课时账户与流水(真相之源)

- 按 **学员 + 课程** 建**课时账户**,有余额;
- 每次变动写一条**课时流水**:`purchase 购买` / `consume 消课` / `refund 退款` / `adjustment 调整`;
- **余额 = 流水累加**,流水是唯一真相来源——不允许"只在学员表存一个剩余数字"。

### 6.3 排课与冲突

- 班级生命周期:`recruiting 招生中` → `active 进行中` → `completed 结课` / `paused 暂停` / `archived 归档`;
- 课次分为**正式班级课次**和**临时课次**;临时课次不建立隐藏班级,直接关联课程;
- 新课次保存独立学员名单快照;学员可以"仅参加本课次",也可以在有权限时"正式加入班级";
- 每个课次保存 `lesson_units`(0–10 整数),仍从"学员 + 课程"课时账户扣减,不区分购买批次;
- 创建 / 修改课次时检查:**同一教室同一时间不可重叠**、**同一老师同一时间不可重叠**;
- 课次发生(签到)后,核心时间不可随意改。

### 6.4 签到 → 扣课时

- 课次签到状态:`present 到课` / `leave 请假` / `absent 缺勤` / `makeup 补课` / `trial 试听`;
- 按状态决定是否扣课时(到课扣、请假 / 缺勤按机构规则),**扣课时即写课时流水、更新余额**;
- 签到对"同一课次 + 同一学员"幂等,不重复扣;
- 余额低于阈值 → 生成**续费提醒**(站内通知,后期可加短信 / 公众号)。
- 管理员可在后台点名;老师可在小程序为自己负责的课次点名。
- 到课 / 迟到 / 缺勤 / 补课按课次 `lesson_units` 扣减;请假 / 试听不扣。

## 8. 核心实体与关系

- **身份**:`accounts` · `account_role_assignments`(含老师权限开关) · `guardians` · `students` · `teachers`
- **商品**:`courses` · `course_packages`
- **获客**:`channels` · `campaigns` · `leads` · `follow_up_records` · `trial_sessions`
- **教学**:`campuses` · `classrooms` · `classes` · `class_enrollments` · `class_sessions` · `class_session_students`
- **考勤课时**:`attendance_records` · `lesson_accounts` · `lesson_transactions`
- **财务**:`orders` · `payments`
- **机构 / 系统**:`organization`(单例:机构身份 + 品牌 VI + 公开页文案) · `settings`(SMTP / 七牛 / 支付密钥,加密) · `notifications` · `audit_logs`

关键关系:

- 一个**联系人(家长)**可绑多个**孩子**;一个孩子可绑多个联系人;
- **家长账号** ↔ 联系人(按手机号);**老师账号** ↔ 老师档案;
- **课时账户**唯一键 = 学员 + 课程;
- **线索 / 订单 / 学员** 均带渠道 / 活动归因。

## 9. 老师权限规则

- 普通授课老师的新能力由账号上的独立开关控制,默认关闭;
- 同时拥有有效 `admin + teacher` 身份的账号,老师能力默认全部开启;
- 普通老师的工作台数据范围默认只包含自己负责/协同的学员、班级和课次;
- `admin + teacher` 双重身份在老师工作台可查看所属机构的全部学员、班级、课次、互动和批阅数据;列表必须标记“我的学员 / 我的班级 / 我的课次”或显示实际负责老师;
- 学员本身没有机构字段,机构学员范围由“机构老师负责的班级成员”与“机构作为课程提供方的课时账户”共同确定;
- 老师端的课程、班级、课次、学员搜索、通知及教室候选必须以老师所属机构和课程的 `providerInstitutionId` 为边界,不得因管理员双重身份扩大到其他机构;
- 老师端课时展示格式为“剩余/总数”;总数按“当前余额 + 历史净消耗课时”计算,以兼容续费、退款和点名更正;
- 双重身份可以在老师工作台处理机构课次的点名、互动和批阅;班级负责人和正式成员结构仍按老师端归属规则操作,跨老师调整可切换管理员身份;
- 老师新建班级时,负责人固定为当前老师,校区随所选教室确定;可建空班或从全部学员中选择初始成员;
- 老师增减班级成员仍校验课程课时账户、班级容量和同课程唯一在班关系;移出班级不改写历史课次名单与点名记录;
- 每位老师都可以查看自己的账号信息并维护公开个人介绍;账号登录标识和角色仍由管理员维护;
- 权限开关只决定"能做什么",资源归属校验决定"能操作谁的数据",两层都必须由后端执行。
